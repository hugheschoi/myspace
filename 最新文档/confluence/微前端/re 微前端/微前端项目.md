我看完三个仓库后，结论先放前面：这套不是传统 `iframe` 或 `single-spa mount/unmount` 型微前端，而是 **Webpack 5 Module Federation + micro-base 运行时基座 + 路由/组件级拼装**。

**一句话架构**
浏览器先加载 `vmi-admin-fe`，主应用通过 Module Federation 拉取 `micro-base` 的运行时能力，创建同一套 `Vue Router / Vuex / i18n`，然后再拉取 `sbs-product-fe` 暴露出来的路由、组件、领域能力，把它们注册进主应用的同一个路由树里。

代码主线：

- `vmi-admin-fe`：主应用、页面外壳、菜单、权限、业务入口。
- `micro-base`：运行时基座，提供 `BootstrapApp`、全局 router/store、插件生命周期、动态加载路由/组件能力。
- `sbs-product-fe`：子应用 monorepo，其中 `projects/scs-product-pms` 暴露 `scsProductPms`，`domains/scm-product` 暴露 `scmProduct`，主应用都在消费。

使用 Promise 加载微前端模块，
remote.ts
```js
const getRemoteModule = (moduleName, entry) =>
  `promise new Promise(${resolveRemoteModule(moduleName, entry)})`;

const resolveRemoteModule = (moduleName, entry) =>
  ((resolve, reject) => {
    // @ts-ignore
    // eslint-disable-next-line no-undef
    const defaultDomain = ___DEFAULT_DOMAIN__;
    // @ts-ignore
    // eslint-disable-next-line no-undef
    const module = ___MODULE__;
    if (window[module]) {
      resolve(window[module]);
      return;
    }
    const url = new URL(defaultDomain || window.sessionStorage.getItem(module) || window.location.origin);
    // @ts-ignore
    // eslint-disable-next-line no-undef
    url.pathname = ___ENTRY___;
    const script = document.createElement('script');
    script.src = url.toString();
    script.onload = () => {
      // the injected script has loaded and is available on window
      // we can now resolve this Promise
      const proxy = {
        // 这里必须用函数，因为 window[module] 是异步加载的，如果直接用 window[module] 会报错
        // @ts-ignore
        get: (...args) => window[module].get(...args),
        init: (...args) => {
          try {
            // @ts-ignore
            return window[module].init(...args);
          } catch (e) {
            // eslint-disable-next-line no-console
            console.log('remote container already initialized');
          }
        },
      };
      resolve(proxy);
    };
    script.onerror = (e: any) => {
      // @ts-ignore
      // eslint-disable-next-line no-undef
      const target = e.target;
      const error = `Loading remote container failed:\n${target?.src || e}\n`;
      console.error(error);
      reject(null);
    };
    // inject this script with the src set to the versioned remoteEntry.js
    document.head.appendChild(script);
  })
    .toString()
    // 替换函数的变量，实现动态 remote
    .replace('___ENTRY___', JSON.stringify(entry))
    .replace('___MODULE__', JSON.stringify(moduleName))
    .replace('___DEFAULT_DOMAIN__', JSON.stringify(getDomainByModule(moduleName)));

export const remoteModules = {
  '@retail/micro-base': getRemoteModule(
    'microBase',
    '/micro-base/microBaseEntry.js'
  ),
  scsProductPms: getRemoteModule('scsProductPms', '/scm-entry/scs-product-pms/scsProductPmsEntry.js'),
};
```

**实现特点**
子应用不是整个页面独立挂载，而是“导出模块”。主应用拿到子应用的 `getRoutes()`、`getComponents()` 后，把它们变成自己路由树的一部分。

React/Vue 混用靠 `micro-base` 适配：

- React 路由转 Vue 路由：[registerRouter.ts](/Users/zhuangbing.cai/Documents/works/micro-base/src/module/router/registerRouter.ts:49)
- Vue 中加载 React 组件：[loadComponent.tsx](/Users/zhuangbing.cai/Documents/works/micro-base/src/module/component/loadComponent.tsx:81)
- React 中加载 Vue 组件：[loadComponent.tsx](/Users/zhuangbing.cai/Documents/works/micro-base/src/module/component/loadComponent.tsx:104)

**最容易讲混的点**
代码里还有 `/admin` PMS iframe 嵌入逻辑，这和 `sbs-product-fe` 微前端不是一回事。  
`sbs-product-fe` 是 Module Federation 子应用；`/admin` PMS 是 iframe 嵌入的另一个系统。

**难点和问题**
1. 远程入口加载失败  
   现象：`Loading remote container failed`、remoteEntry 404。  
   解决：检查 `remotes.ts` 的 remote name、entry path、环境变量、Network 里的 `xxxEntry.js`。

2. 子应用 chunk 404  
   现象：remoteEntry 加载成功，但页面组件懒加载失败。  
   原因通常是 `publicPath` 不对。  
   解决：确认子应用 dev/prod publicPath 是 `/scm-entry/{moduleName}/`。

3. 依赖版本冲突  
   Vue、React、vue-router、vuex 都配置了 singleton。版本不一致会出现 hook 报错、router 异常、样式组件异常。  
   解决：主子应用核心依赖尽量对齐，尤其 Vue 2.7、React 18。

4. 路由不显示或 403  
   可能原因：`meta.permissions`、`hidden`、路由 name 重复、父子 path 不对。  
   解决：先看路由是否进了 `registeredRoutes`，再看权限过滤和菜单过滤。

5. 初始化顺序  
   子应用很多代码依赖 `$gt`、`i18n`、`window.__GLOBAL_DATA__`。  
   主应用在 [init-global-data.ts](/Users/zhuangbing.cai/Documents/works/scs/vmi-admin-fe/src/init-global-data.ts:20) 注入给子应用的 API、store、router、request。过早 import 依赖这些内容的模块，容易 undefined。

6. 本地联调复杂  
   建议三个仓库分别启动，并在 `vmi-admin-fe/.env.local` 显式指定：
   ```bash
   microBaseEnv=local
   microBaseLocal=http://localhost:8000
   scsProductPmsEnv=local
   scsProductPmsLocal=http://localhost:3001
   scmProductEnv=local
   scmProductLocal=http://localhost:3002
   ```

   启动顺序可以是：
   ```bash
   # micro-base
   yarn start

   # sbs-product-fe: scsProductPms
   PORT=3001 pnpm start:sp

   # sbs-product-fe: scmProduct，如需要本地调共享 product domain
   PORT=3002 pnpm start

   # vmi-admin-fe
   yarn start
   ```

你讲的时候可以这样收尾：**这套架构的核心价值是主应用统一登录、权限、菜单、布局、请求和监控，子应用只负责输出业务路由和组件；真正的拼装发生在运行时，由 Module Federation 拉代码，由 micro-base 统一注册到同一套 router/store 中。**
