如果你只是看官方 Demo，会觉得 Module Federation 很优雅：

```text
Host -> Remote -> Button
```

但真实生产环境里，**80% 的问题都不是配置问题，而是运行时、部署、版本和团队协作问题。**

我按实际踩坑频率排序讲。

---

# 1. remoteEntry 缓存问题（最常见）

这是几乎所有团队都会遇到的。

## 场景

remote 发布新版本：

```text
v1
remoteEntry.js
button.abc123.js
```

升级：

```text
v2
remoteEntry.js
button.xyz789.js
```

用户浏览器缓存了旧的：

```text
remoteEntry.js(v1)
```

但 CDN 已经删除：

```text
button.abc123.js
```

结果：

```text
Loading chunk failed
ChunkLoadError
```

页面直接白屏。

---

## 实际现象

用户看到：

```text
Cannot load remote module
ChunkLoadError
```

Sentry 里疯狂报警。

---

## 解决方案

remoteEntry 永远不要强缓存：

```http
Cache-Control: no-cache
```

chunk 才长期缓存：

```http
Cache-Control: max-age=31536000
```

很多大厂都是：

```text
remoteEntry.js
不缓存

chunk.xxx.js
永久缓存
```

---

# 2. React 多实例

这是第二大坑。

## 场景

Host：

```json
react: 18.2.0
```

Remote：

```json
react: 18.3.x
```

或者：

```json
react: 18.2.0
```

但是 shared 配置没写。

结果：

```text
Host React
Remote React
```

两份实例。

---

## 现象

经典报错：

```text
Invalid hook call
```

或者：

```text
Cannot read properties of null
```

或者 Context 失效：

```jsx
useContext(UserContext)
```

返回：

```js
undefined
```

---

## 解决

必须：

```js
shared: {
  react: {
    singleton: true
  },
  "react-dom": {
    singleton: true
  }
}
```

---

# 3. Shared 版本地狱

很多团队以为：

```js
singleton: true
```

就结束了。

实际上：

```text
Host React 18
Remote React 17
```

谁赢？

---

Webpack 有版本协商机制：

```text
version negotiation
```

但结果经常不是你想的。

例如：

```text
Host 提供 React18
Remote 要 React17
```

Remote 可能直接使用 React18。

然后：

```text
某些旧代码崩了
```

---

大型项目常见做法：

```text
所有 MF 应用统一锁版本
```

例如：

```text
react 18.2.0
react-dom 18.2.0
```

统一升级。

---

# 4. Remote 不可用

真实世界：

```text
Host 正常
```

但：

```text
app-order
```

挂了。

或者：

```text
CDN故障
```

或者：

```text
remoteEntry 404
```

---

此时：

```js
import("order/App")
```

直接 reject。

---

很多团队第一次上线：

```text
一个 remote 挂
整个首页白屏
```

---

解决方案：

```js
try {
  const App = await import("order/App");
} catch {
  return FallbackPage;
}
```

或者：

```jsx
<Suspense>
  <ErrorBoundary>
    <RemoteApp />
  </ErrorBoundary>
</Suspense>
```

必须有降级。

---

# 5. 类型系统崩掉

TS 开发体验非常差。

例如：

```js
import("app1/Button")
```

TS 根本不知道：

```text
Button 是什么
Props 是什么
```

因为：

```text
编译时不存在
运行时才存在
```

---

解决方案通常有三种：

### 方法1

手写：

```ts
declare module "app1/Button";
```

非常原始。

---

### 方法2

发布类型包

```text
@company/app1-types
```

Host 安装：

```bash
npm install @company/app1-types
```

---

### 方法3

自动生成 d.ts

现在很多团队都这么做。

例如：

```text
@module-federation/dts-plugin
```

---

# 6. CSS 污染

Remote：

```css
.button {
  color: red;
}
```

Host：

```css
.button {
  color: blue;
}
```

谁生效？

不知道。

---

最后：

```text
今天红
明天蓝
```

取决于加载顺序。

---

解决方案

### CSS Module

```css
.button_xxx123
```

---

### Emotion

```jsx
styled-components
emotion
```

---

### Shadow DOM

极端方案。

# 7. 公共状态共享

很多团队都会问：

```text
Redux 怎么共享？
```

---

Host：

```text
userStore
```

Remote：

```text
cartStore
```

---

问题来了：

```text
登录态怎么同步？
```

---

很多团队第一版：

```text
多个 Redux Store
```

最后：

```text
状态同步地狱
```

---

比较成熟的方案：

### Host 提供状态

```js
exposes: {
  "./userStore": "./store"
}
```

Remote：

```js
import("host/userStore")
```

---

或者：

```text
zustand
```

共享一个 Store。

---

# 8. 路由冲突

Host：

```text
/orders
```

Remote：

```text
/orders/list
/orders/detail
```

---

Remote 经常：

```jsx
<BrowserRouter>
```

再套一层。

结果：

```text
history 混乱
```

---

生产实践：

Remote 不管理顶级 Router。

只接受：

```jsx
<Route />
```

由 Host 控制。

# 9. 发布顺序问题

场景：

Host：

```js
import("order/NewFeature")
```

---

但：

```text
Host 先上线
```

Remote：

```text
还没上线
```

---

结果：

```text
Module not found
```

---

很多团队会出现：

```text
A团队发版
B团队没发版
线上炸了
```

---

解决：

### 版本兼容

```text
Host v3
兼容
Remote v2
Remote v3
```

---

或者：

```text
Feature Flag
```

控制开关。

# 10. 首屏性能反而变差

很多人以为：

```text
MF = 更快
```

实际上经常更慢。

---

以前：

```text
1个 bundle
```

现在：

```text
host
 ↓
remoteEntry
 ↓
remote chunk
 ↓
shared chunk
```

变成：

```text
N次网络请求
```

---

特别是：

```text
10个 remote
```

首页直接：

```text
20~50个请求
```

---

很多团队最后变成：

```text
微前端成功了
性能死了
```

# 真实大型项目里最大的坑

如果让我按影响排序：

| 排名 | 问题             | 严重程度  |
| -- | -------------- | ----- |
| 1  | remoteEntry 缓存 | ⭐⭐⭐⭐⭐ |
| 2  | Remote 不可用导致白屏 | ⭐⭐⭐⭐⭐ |
| 3  | React 多实例      | ⭐⭐⭐⭐⭐ |
| 4  | 发布顺序不一致        | ⭐⭐⭐⭐  |
| 5  | Shared 版本冲突    | ⭐⭐⭐⭐  |
| 6  | TS 类型同步        | ⭐⭐⭐   |
| 7  | 状态共享           | ⭐⭐⭐   |
| 8  | CSS 污染         | ⭐⭐⭐   |
| 9  | Router 冲突      | ⭐⭐    |
| 10 | 首屏性能下降         | ⭐⭐    |

很多公司做了一两年后会发现：

> Module Federation 最难的不是技术，而是“多个团队独立发布但又必须保持契约兼容”的工程治理问题。

技术层面的坑几周能填完，团队协作和版本治理的问题往往会持续几年。
