这其实是很多高级前端面试里的真实情况。

我先给你一个结论：

> **没做过 Module Federation 项目，不要假装做过；但完全可以把它作为“深入研究过的技术专题”来讲。**

这是两个完全不同的定位。

## 你应该准备到什么深度

如果我是面试官。

你能回答下面这些问题，就已经超过 80% 候选人。

### 第一层

什么是 Module Federation？

回答：

> Webpack 5 提供的运行时模块共享机制。
>
> Host 可以在运行时加载 Remote 暴露的模块，而不是在构建阶段打包进去。

---

### 第二层

remoteEntry 是什么？

回答：

> remoteEntry 本质上是一个模块注册表（Container）。
>
> 它暴露 get 和 init 方法。
>
> Host 先加载 remoteEntry，然后通过 get 获取远程模块工厂，再执行工厂获得模块。

---

### 第三层

shared 是什么？

回答：

> shared 用于运行时共享依赖。
>
> React、ReactDOM 通常配置 singleton。
>
> 这样 Host 和 Remote 可以使用同一个 React 实例，避免 Hook 和 Context 失效。

---

### 第四层

为什么 React 要 singleton？

回答：

> React Context、Hook 都依赖内部全局状态。
>
> 如果 Host 和 Remote 加载两份 React，会出现 Invalid Hook Call 等问题。

---

### 第五层

线上最大的问题是什么？

回答：

> 我没有线上经验，但根据调研和社区实践，最常见的问题是：
>
> * remoteEntry 缓存
> * Remote 服务不可用
> * React 多实例
> * Shared 版本冲突
> * 发布顺序治理

这就已经很像一个认真研究过的人了。
