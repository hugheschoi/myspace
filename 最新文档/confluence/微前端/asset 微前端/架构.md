这套 `asset` 的微前端架构，核心上是一个 **“主应用提供壳子与共享上下文，子应用提供业务模块，双方通过 Module Federation 双向装配”** 的设计。和你前面看的 `vmi-admin-fe + micro-base` 不太一样，这里没有单独抽一个 `micro-base` 仓库，而是把“基座能力”直接放进了主应用 `asset-ui` 里。

**整体结构**

`asset-ui` 是主应用，也是运行时壳子。它在 [webpack.config.js](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/webpack.config.js:226) 里做了两件事：

- 暴露 `Shared/app`，也就是 `src/app/main.js`
- 远程消费 `AssetPC`，通过 `window.LOAD_REMOTE_ENTRY("AssetPC", "asset-pc", "remoteEntry.react.js")` 动态加载子应用

对应代码：

```js
new ModuleFederationPlugin({
  name: 'Shared',
  filename: 'sharedEntry.js',
  exposes: {
    './app': path.resolve(__dirname, 'src/app/main.js'),
  },
  remotes: {
    AssetPC: 'promise window.LOAD_REMOTE_ENTRY("AssetPC", "asset-pc", "remoteEntry.react.js")',
  },
})
```

`asset-mfe` 是子应用仓库，`apps/asset-pc` 这个子应用在 [moduleFederationConfig.js](/Users/zhuangbing.cai/Desktop/资料/asset/asset-mfe/apps/asset-pc/config/moduleFederationConfig.js:17) 里也做了两件事：

- 暴露 `./module`
- 反向依赖主应用的 `Shared/app`

```js
module.exports = {
  name: moduleName,
  filename: 'remoteEntry.react.js',
  exposes: {
    './module': paths.mfModule,
  },
  remotes: {
    Shared: 'promise window.LOAD_REMOTE_ENTRY("Shared", "ssc-assets", "sharedEntry.js")',
  },
  shared: dependenciesShared,
};
```

所以它不是简单的“主应用 import 子应用”，而是：

- 主应用把自己的启动能力暴露出去
- 子应用启动时先拿主应用的 `Shared/app`
- 子应用再把自己的模块 `./module` 提供给主应用注册

这是一种**双向 Federation**。

**运行时链路**

最关键的运行流程在这几处：

1. `asset-ui` 先定义远程资源地址解析器  
   [moduleEntryBaseURL.ts](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/src/moduleEntryBaseURL.ts:45)

这里的 `window.LOAD_REMOTE_ENTRY` 会根据 `appId` 拼接脚本地址，然后插入 `<script>` 去加载 remote entry。开发环境里 `asset-pc` 默认走 `/module-federation`，生产环境走 `/asset-pc`。

```js
window.LOAD_REMOTE_ENTRY = function (moduleName, appId, filename = 'remoteEntry.js') {
  if (window[moduleName]) {
    // have loaded elsewhere
    return window[moduleName];
  }
  if (!ENTRY_CACHE[moduleName]) {
    ENTRY_CACHE[moduleName] = new Promise((resolve, reject) => {
      const urls = [window.MODULE_ENTRY_BASE_URL[appId]].flat(Infinity);
      const load = () => {
        const url = urls.shift();
        if (!url) {
          load();
          return;
        }
        const script = document.createElement('script');
        const complete = () => {
          script.onerror = script.onload = null;
          script.parentNode && script.parentNode.removeChild(script);
        };
        if (url.endsWith('/')) {
          script.src = `${url}${filename}`;
        } else {
          script.src = `${url}/${filename}`;
        }
        script.onload = () => {
          complete();
          if (!window[moduleName] && urls.length) {
            load();
            return;
          }
          // the injected script has loaded and is available on window
          // we can now resolve this Promise
          let inited = false;
          const proxy = {
            get: (request) => window[moduleName].get(request),
            init: (arg) => {
              if (inited) return;
              try {
                window[moduleName].init(arg);
                inited = true;
              } catch (e) {
                // TODO need to report this error
                throw new Error('remote container init error: ' + e.message);
              }
            },
          };
          resolve(proxy);
        };
        script.onerror = () => {
          complete();
          reject(new Error('remote container load error: ' + script.src));
        };
        document.head.appendChild(script);
      };
      load();
    });
  }
  return ENTRY_CACHE[moduleName];
};
```

3. `asset-ui` 的 `run()` 负责真正注册子应用  
   [main.js](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/src/app/main.js:37)

`run(modules)` 里先做：

- `prepareModuleSource(modules)`：注册子应用 routes / stores / menus
- `initTransilation(...)`：初始化翻译
- 再启动 Vue 根实例

4. 子应用模块如何被注册  
   [module-federation.ts](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/src/app/register/module-federation.ts:80)

`registerModule()` 会读取子应用导出的：

- `routes`
- `stores`
- `menus`
- `packageInfo`
- `beforeRegistration`
- `afterRegistration`
- `isReact`

然后：

- `router.addRoute(route)` 注册路由
- `store.registerModule(...)` 注册 store
- `store.commit('addMenus', menus)` 合并菜单
- `store.commit('setRouteList', ...)` 记录子应用路由

也就是说，**子应用不是 iframe，也不是整个 App 被挂进去，而是把自己的“业务模块描述”交给主应用装配。**

**子应用的输出形态**

`asset-pc` 暴露的是 `src/moduleEntries/react-project.tsx`，见 [react-project.tsx](/Users/zhuangbing.cai/Desktop/资料/asset/asset-mfe/apps/asset-pc/src/moduleEntries/react-project.tsx:1)：

```ts
const exportDefault = {
  isReact: true,
  routes: vueRoutes,
  reactRoutes,
  packageInfo: {
    name: __PACKAGE_INFO_NAME__,
    dependencies: {},
  },
};
```

这里很有意思，子应用同时导出两套路由：

- `reactRoutes`：React 自己的路由定义
- `vueRoutes`：把 React 路由转换成 Vue 可注册路由后的结果

这个转换来自 `@scfe-common/micro-frontend-utils`：

- [react.tsx](/Users/zhuangbing.cai/Desktop/资料/asset/asset-mfe/apps/asset-pc/src/common/router/react.tsx:5)
- [vue.tsx](/Users/zhuangbing.cai/Desktop/资料/asset/asset-mfe/apps/asset-pc/src/common/router/vue.tsx:7)

也就是说，`asset-mfe` 自己先把 React 路由“翻译”成一份 Vue 路由结构，再交给 `asset-ui` 去挂载。

**Vue 宿主如何承载 React 页面**

`asset-ui` 本身是 Vue2 主壳，但它也有自己的 React 页面体系。桥接逻辑在 [bridge.ts](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/src/utils/bridge.ts:30)。

核心逻辑是：

- 如果 route 有 React component，就用 `reactContainerFactory(...)` 包一层 Vue 组件
- 如果只是菜单父节点，没有实际组件，就用 `ComponentLayout`

所以最终效果是：

- Vue Router 管路由树
- Vue 页面照常渲染
- React 页面被包装后挂进 Vue 容器里渲染

这解释了为什么 `asset-ui` 可以同时承载 Vue 老页面和 React 子应用页面。

**为什么这套架构成立**

它的本质分工可以这样记：

- `asset-ui`
  负责启动、壳子、Vue Router、Vuex、菜单、权限、翻译、基础上下文
- `asset-mfe`
  负责按业务域拆出来的 React 模块、页面路由、部分 store/菜单描述
- `LOAD_REMOTE_ENTRY`
  负责运行时找到 remote entry
- `Module Federation`
  负责把双方的模块系统接起来

**这套方案的几个特点**

1. 主应用兼任“基座”
   没有独立 `micro-base`，而是 `asset-ui` 自己暴露 `Shared/app`，把基座职责内嵌进主应用。

2. 双向依赖很明显
   `asset-ui` 消费 `AssetPC/module`，`asset-pc` 又消费 `Shared/app`。这说明子应用不是完全自治，而是依赖主应用上下文启动。

3. React/Vue 混合运行是第一公民
   这不是后期兼容 hack，而是架构里明确设计过的能力。

4. 子应用仓库更像“业务模块仓库”
   `asset-mfe` 里不仅有 `apps/asset-pc`，还有 `packages/src/biz-modules/...`，说明它是一个多应用 + 共享业务包的 monorepo。

**你讲解时可以用这句话概括**

> `asset-ui` 不是单纯的 host，而是把 host 和 base 合在一起了；`asset-mfe` 不是完整独立站点，而是把业务模块通过 Module Federation 输出给主应用，由主应用统一注册路由、菜单、store 和上下文。

**容易踩的点**

- 远程入口路径是否正确  
  `asset-ui` 开发环境默认走 `/module-federation`，见 [moduleEntryBaseURL.ts](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/src/moduleEntryBaseURL.ts:5)；`asset-mfe` 也有对应 proxy，把 `/module-federation/` 改写到真实远端，见 [proxy.js](/Users/zhuangbing.cai/Desktop/资料/asset/asset-mfe/apps/asset-pc/config/proxy.js:193)。

- 子应用路由注册成功但页面不显示  
  通常是 React route 转 Vue route 的桥接、容器组件、或 basename / namespace 没对齐。

- store / menu 命名冲突  
  `registerStores()` 里已经显式防重名，重复会报错，见 [module-federation.ts](/Users/zhuangbing.cai/Desktop/资料/asset/asset-ui/src/app/register/module-federation.ts:63)。

- shared 依赖版本漂移  
  `asset-mfe` 把几乎所有 dependencies 自动声明成 shared，见 [moduleFederationConfig.js](/Users/zhuangbing.cai/Desktop/资料/asset/asset-mfe/apps/asset-pc/config/moduleFederationConfig.js:5)。这能减少重复实例，但也意味着版本协商更敏感。
