AI Codegen Engineering

SDD / TDD 驱动的生码工程

把 PRD、TD、接口文档和仓库上下文变成可追踪、可验证、可 review 的代码变更流程。

SDD定义要做什么，以及为什么这样做。
TDD定义怎么验收，以及哪里会回归。
Plan定义改哪些文件、按什么顺序改。
Verify用命令和 review 关闭风险。
Problem

AI 生码最大的问题，不是写不出代码

真正难的是控制上下文、意图、边界和验证，让每一行代码都能被解释和回归。

Context

需求散在多处

PRD、TD、YAPI、Confluence、Jira、路由文件、旧代码都可能各说一部分。没有索引，AI 很容易补脑。

Scope

改动边界模糊

一个字段可能经过 schema、BLL、API、详情展示和提交格式化。缺少计划时，容易只改到表面。

Verify

验证被后置

如果测试和验收点等代码写完才补，常常只验证 happy path，遗漏权限、区域、旧数据和回归。

02
Mental Model

把生码工程拆成四份合同

每个产物都服务于一个问题：为什么改、怎么验、怎么改、改完是否可信。

01

Source Index

把 PRD、TD、代码上下文编号，后续每个结论都能追溯来源。

02

SDD

把功能、页面、状态、接口和风险写成实现合同。

03

TDD

把功能点转成测试矩阵和手工验收步骤。

04

Plan + Verify

小步 patch、定向校验、review 清单，避免一次性大改。

03
Workflow

一次生码任务的七步流水线

这个流程故意慢半拍：先把意图和验收钉住，再让 AI 写代码。

1
Source收集 PRD / TD / API / 代码线索
2
Context定位路由、页面、BLL、schema、接口
3
SDD定义功能点、状态和协议
4
TDD设计测试矩阵和验收路径
5
Plan列文件、顺序、风险和命令
6
Patch按计划小步改代码
7
Review校验 diff、命令结果和遗留风险
04
Engineering Structure

本地 skill 的工程结构

skill 像一个轻量 Harness：流程在 `SKILL.md`，模板在 `references`，脚手架在 `scripts`。

~/.codex/skills/ai-codegen-sdd-tdd/ SKILL.md references/ codegen-run-template.md review-checklist.md scripts/ create_codegen_run.py
SKILL

定义何时触发、如何收集上下文、怎样按 SDD/TDD 生码。

Template

约束每次任务都产出 source index、SDD、TDD、plan 和 verification。

Script

快速在目标 repo 下创建一次生码任务目录，便于沉淀和复盘。

05
How To Run

一次需求怎么启动

你可以手动跑脚本，也可以直接把 PRD/TD 给 Codex，让它按 skill 创建并填写产物。

1 先创建一块独立工作台，避免 SDD、TDD、代码计划混进业务目录。
python3 ~/.codex/skills/ai-codegen-sdd-tdd/scripts/create_codegen_run.py \ --name supplier-origin-code \ --root /Users/zhuangbing.cai/Documents/works/sbs-supplier-fe
生成文件用途
sdd.md写清楚功能设计和接口协议。
tdd.md写清楚测试矩阵和手工验收。
implementation-plan.md写清楚文件、顺序和风险。
verification-report.md记录命令结果、review 和残余风险。
06
Template Usage

模板不是让你手填，是让 AI 有栏杆

你提供链接和目标，Codex 负责读资料、填文档、改代码、跑校验。

阶段你给什么Codex 做什么产物
输入PRD / TD / YAPI / Confluence / 目标路由建立来源索引，标记缺失信息Source Index
设计业务目标和约束拆功能点、页面、状态、接口协议SDD
测试验收口径或关键 case生成测试矩阵和网络 payload 检查TDD
执行确认或默认按计划走小步 patch、复用现有模式Code Diff
收口目标校验范围跑 lint/test、review diff、写风险Verification Report
07
Example Prompt

以后可以这样直接发起

把“帮我生码”改成“按 SDD/TDD 生码”，AI 的输出会明显更可控。

用 ai-codegen-sdd-tdd 帮我做这个需求： PRD: https://confluence...pageId=xxx TD: https://confluence...pageId=yyy 目标仓库: sbs-supplier-fe 页面: /frs/supplier/request/create 要求: - 先生成 SDD/TDD/Plan - 再实现代码 - 最后跑 targeted lint 并写 verification report
✓先定位路由和页面文件，不猜路径。
✓接口字段来自 TD/YAPI，不把展示值污染原始数据。
✓patch 顺序可回滚，校验命令和 warning 单独记录。
✓最终回答直接告诉你改了什么、怎么验、还剩什么风险。
08
Review Gate

生码不是结束，review 才是闸门

review-checklist.md 把常见翻车点固定下来，尤其适合多仓、多路由、多接口字段的 FRS 场景。

Traceability

可追溯

  • 每个行为映射到 SDD
  • 每个接口字段映射到 TD
  • 推断明确标记
Behavior

行为稳定

  • 默认值和区域逻辑不偏
  • 不污染原始接口数据
  • 保留权限和旧流程
Verification

验证闭环

  • 跑 targeted lint / test
  • 记录已有 warning
  • 留下手工验收路径
09
Takeaway

让 AI 写代码之前，先让它写清楚“为什么”和“怎么验”

这套工程的价值不是多一层文档，而是让每次生码都能被追踪、被复盘、被局部验证，也能放心交给团队 review。

Start

给 PRD / TD / 目标页面，启动一次 codegen run。

Control

用 SDD/TDD/Plan 控制 AI 的自由度。

Ship

用验证报告和 review 清单关闭风险。
