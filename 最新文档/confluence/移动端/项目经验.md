下面这版可以直接放进简历的“项目经验”，偏高级前端/架构向，重点突出双端、Native 交互、离线包和工具能力。

**Management App H5 离线包与双端架构建设**  
**项目角色：前端核心开发 / 架构优化**  
**技术栈：React、TypeScript、Vite、Webpack Module Federation、JSBridge、Hybrid WebView、离线包、Monorepo、pnpm、Lerna**

Management App 是面向仓储/物流管理场景的 Hybrid 应用，承载移动端 H5、PC Dashboard 及多业务子应用。项目重点解决弱网环境下 H5 加载慢、APP 内多业务离线包发布耦合、PC/H5 重复研发、Native 能力接入分散等问题。

**主要工作：**

- 参与设计并落地 H5 离线包方案，将 HTML、JS、CSS、图片、i18n 等静态资源构建为 `vendor/bundle` 离线包，通过 `verify.json`、zip md5、manifest 配置实现资源完整性校验与版本管理，提升弱网场景下页面加载稳定性。

- 基于 Vite 插件扩展构建流程，在构建阶段自动改写资源 URL，追加 `_offl_id`、`_app_id` 等离线包识别参数，使 Android WebView 能根据请求参数映射本地离线资源，并在异常时回退线上资源。

- 推动单应用离线包向多应用离线包演进，引入 `biz_id -> app_id` 的业务拆包模型，支持不同业务模块独立发布、灰度和回滚，降低主包体积和跨业务发布互相影响的风险。

- 参与 Order Tracking 等业务从主 H5 包中拆分为独立子应用，处理旧路径 `.html` 与新路由的兼容、Apollo 路由切换、旧版 APP 与新版多应用离线包协议兼容等迁移问题。

- 负责 H5 与 Android Native 的 JSBridge 交互封装与联调，接入页面跳转、状态栏控制、底部 Tab 红点、离线包更新检测、主动更新、APP 信息获取、权限检测、日志上传、网络诊断等 Native 能力。

- 设计并维护 JSAPI 调试页面，支持 `getOfflineInfo`、`checkUpgradeInfo`、`updateOfflinePkg`、`getAppInfo` 等 Native 接口自测，提升 Android / H5 联调效率和问题定位效率。

- 建设 PC/H5 双端适配研发模式，通过 `applications` 统一业务出口、`isolate` 隔离端侧差异，并基于构建 alias 自动切换 `index.h5` / `index.pc` 实现，使页面逻辑、数据模型和业务组件可在移动端与 PC 端复用。

- 抽象双端差异能力，包括路由跳转、用户/站点信息获取、图表参数、帮助弹窗、表格组件、布局组件等，减少业务代码中的端判断，提升多端需求交付效率。

- 参与 PC Dashboard 接入 Module Federation 和版本管理能力，通过带版本号的 `remoteEntry`、`version-info.json`、灰度版本配置，实现 PC 子应用按版本加载及灰度发布。

- 支持离线包升级体验优化，通过 `checkUpgradeInfo` 与 `syncBadges` 实现弱提醒红点机制，减少强制弹窗和重启对用户现场操作的打断。

**项目成果：**

- 建立了 H5 离线包从构建、上传、版本创建、APP 下载、WebView 本地命中到异常兜底的完整链路。
- 支持业务级离线包独立发布和回滚，降低多团队并行迭代时的发布耦合。
- 沉淀 PC/H5 双端适配架构，减少重复开发成本，提高 Dashboard 类需求复用效率。
- 完善 H5 与 Android Native 的 Bridge 能力接入和调试工具，提高 Hybrid 场景下问题定位和联调效率。
