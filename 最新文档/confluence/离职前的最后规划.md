### Management App H5 离线包与 PC/H5 双端架构建设

项目角色：前端核心开发 / 架构优化  
技术栈：React、TypeScript、Vite、Webpack Module Federation、JSBridge、Hybrid WebView、离线包、Monorepo、pnpm、Lerna

Management App 是面向仓储、物流和管理场景的 Hybrid 应用，承载移动端 H5、PC Dashboard 及多个业务子应用。项目重点解决弱网环境下 H5 加载慢、App 内多业务离线包发布耦合、PC/H5 重复研发、Native 能力接入分散等问题。

- 参与设计并落地 H5 离线包方案，将 HTML、JS、CSS、图片、i18n 等静态资源构建为 vendor / bundle 离线包，通过 `verify.json`、zip md5、manifest 配置实现资源完整性校验与版本管理。
- 基于 Vite 插件扩展构建流程，在构建阶段自动改写资源 URL，追加 `_offl_id`、`_app_id` 等离线包识别参数，使 Android WebView 可根据请求参数映射本地离线资源，并在异常场景回退线上资源。
- 推动单应用离线包向多应用离线包演进，引入 `biz_id -> app_id` 的业务拆包模型，支持不同业务模块独立发布、灰度和回滚，降低主包体积和跨业务发布互相影响的风险。
- 参与 Order Tracking 等业务从主 H5 包中拆分为独立子应用，处理旧路径 `.html` 与新路由兼容、Apollo 路由切换、旧版 App 与新版多应用离线包协议兼容等迁移问题。
- 负责 H5 与 Android Native 的 JSBridge 交互封装与联调，接入页面跳转、状态栏控制、底部 Tab 红点、离线包更新检测、主动更新、App 信息获取、权限检测、日志上传、网络诊断等 Native 能力。
- 设计并维护 JSAPI 调试页面，支持 `getOfflineInfo`、`checkUpgradeInfo`、`updateOfflinePkg`、`getAppInfo` 等 Native 接口自测，提升 Android / H5 联调和问题定位效率。
- 建设 PC/H5 双端适配研发模式，通过 `applications` 统一业务出口、`isolate` 隔离端侧差异，并基于构建 alias 自动切换 `index.h5` / `index.pc`，提升页面逻辑、数据模型和业务组件复用能力。
- 参与 PC Dashboard 接入 Module Federation 和版本管理能力，通过带版本号的 `remoteEntry`、`version-info.json`、灰度版本配置，实现 PC 子应用按版本加载及灰度发布。

项目成果：建立了 H5 离线包从构建、上传、版本创建、App 下载、WebView 本地命中到异常兜底的完整链路；支持业务级离线包独立发布和回滚；沉淀 PC/H5 双端适配架构，减少重复开发成本并提升 Hybrid 场景下问题定位效率。

### Transify 前端国际化翻译工具

项目角色：工具建设 / 国际化规范沉淀  
技术栈：TypeScript、Vue i18n、Rollup、MD5、Browser API、SessionStorage、CLI 工具链

Transify 是面向供应链前端业务的国际化翻译工具，用于统一生成翻译 Key、收集业务文案、对接翻译平台，并支持开发态调试和命令行自动化扫描上传。工具通过 `$gt` 翻译函数降低业务侧国际化接入成本，提升翻译 Key 管理的一致性和可维护性。

- 设计并实现统一翻译 Key 生成规则，基于 `project + namespace + label` 生成稳定 16 位 MD5 Key，解决手写 Key 不规范、命名冲突和维护成本高的问题。
- 封装 `generateTransifyVueI18n`，基于 vue-i18n 生成统一 `$gt` 翻译函数，支持默认文案、命名空间、插值参数和生产环境 fallback。
- 实现开发态翻译 Key 自动收集能力，在缺失翻译时将 `key -> label` 暂存到 `sessionStorage`，并提供控制台导出、清理等调试工具。
- 梳理翻译工具完整链路，包括 Key 生成、运行时翻译、开发态收集、JSON 导出、CLI 扫描上传、语言包下载等流程。
- 参与规范化国际化使用方式，明确 `$gt` 静态字符串、namespace、插值参数等最佳实践，降低翻译冲突和扫描遗漏风险。

项目成果：降低业务项目国际化接入复杂度，开发者只需编写默认文案即可生成规范翻译 Key；提升翻译 Key 的一致性和可追踪性；支持开发态自动收集缺失文案，沉淀为可复用于多个前端业务项目的国际化工具能力。

### AICR / IBS CLI - AI Code Review Shift-Left 工具

项目角色：CLI 工具开发 / AI 研发流程接入  
技术栈：Node.js、CommonJS、Commander、Git Hooks、Shell、Cursor Deep Link、macOS URL Scheme、GitLab MR、REST API

AICR / IBS CLI 是内部 AI Code Review 命令行工具，用于在开发阶段自动采集 Git 变更上下文、创建后端审查会话，并通过 Cursor Deep Link 触发 AI Code Review 工作流，实现代码审查前置化与本地研发流程集成。

- 设计并实现 `ibs cr` 核心审查流程，支持暂存区审查、分支对比、Commit 对比、GitLab MR URL 审查和 rerun 复跑模式，覆盖多种开发提交流程。
- 封装 Git 数据采集能力，基于 `git diff --numstat --patch` 一次性获取文件变更统计与完整 patch，并结合远程过滤规则排除测试、mock、docs、删除文件等低价值内容，降低审查噪音和上传体积。
- 接入后端 CR Session API，将 workspace、用户信息、项目标识、分支信息、commit 列表、diff 文件、Cursor 自定义规则等上下文结构化上传，为服务端分批审查和重复检测提供数据基础。
- 实现 Cursor Deep Link 调用链路，将后端返回的 `session_id` 自动转换为 Cursor prompt，触发 `cr_shift_left_batch_review` 工具调用，减少用户手动复制粘贴和操作成本。
- 设计 Git Hooks 管理模块，支持全局 `pre-push`、`pre-commit`、`post-commit` 安装与卸载，并兼容本地 `.git/hooks`、Husky、自定义 `core.hooksPath` 等多种 hooks 配置方式。
- 实现本地 hook wrapper 机制，对已有 hook 自动备份、包装和恢复，保证 AI CR 逻辑接入的同时不破坏项目原有 lint、test、commit 校验流程。
- 支持 macOS `ibs://` URL Scheme 注册，使浏览器或平台页面可通过链接直接唤起本地 CLI，实现审查任务从平台到本地 IDE 的闭环触发。

项目成果：将 AI Code Review 从人工发起的后置流程前移到 `git push` 或本地命令执行前，通过 CLI、Git Hooks、后端 Session 和 Cursor 工具调用串联研发工作流，提升代码审查触达率和开发体验。
