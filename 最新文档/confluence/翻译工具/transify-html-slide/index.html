01
01 / Why

主要解决的问题：翻译 Key 管理从人肉约定变成工具约束

业务快速迭代时，国际化问题通常不是“能不能翻译”，而是“能否稳定、低成本、可追踪地翻译”。

命名不统一 手写 Key 容易出现风格差异、重复命名和语义漂移。
收集靠人工 新增文案散落在页面和组件中，遗漏后只能在测试阶段暴露。
平台链路断层 代码、翻译平台、本地语言包之间需要人工搬运。
排查成本高 生产环境不能暴露 Key，开发环境又要能快速定位缺失文案。

项目目标：业务只写默认文案，工具负责后续链路

用统一 $gt 函数承接业务接入，用稳定 Key 算法承接平台映射，用开发态与 CLI 工具承接收集和流转。

开发体验

默认文案即入口

开发者写 $gt('Order Id')，不再关心手工命名和 Key 维护。

稳定映射

算法生成规范 Key

通过 project + namespace + label 生成 16 位 MD5 Key，减少人为差异。

工程闭环

收集、上传、下载闭环

开发态自动收集缺失 Key，配合 CLI 完成扫描、上传、下载。

当前仓库主要承载运行时 Client；完整方案中，CLI 负责静态扫描与平台自动化。

04
04 / Runtime Flow

运行时思路：先算 Key，再决定翻译、兜底或收集

同一个 $gt 调用在开发、测试、生产环境下保持一致入口，但分支策略不同。

调用 $gt 传入 label、namespace、options
生成 Key project + namespace + label
检查资源 i18n.te(computedKey)
缺失处理 prod 返回 label，dev 收集 key
输出文案 i18n.t(key, options)

关键点：生产环境避免把内部 Key 暴露给用户；开发环境则尽可能把缺失翻译沉淀出来，形成后续上传输入。

05
05 / Key Algorithm

关键实现一：稳定 Key 生成

Key 既要足够短，又要能稳定复现，还要支持同文案不同语义。

md5('${project}_${namespace}_${label}')
.slice(8, 24)
  • project 保证不同项目之间 Key 空间隔离。
  • namespace 解决同一个英文文案在不同业务语义下的冲突。
  • label 保留默认文案，让业务开发不需要先想 Key。
  • 截取 16 位降低 Key 长度，方便资源文件和页面排查。
function md516(str: string): string {
  return md5(str) && md5(str).slice(8, 24);
}

export function generateKey({ label, project, namespace }) {
  if (!project || !label) return '';
  const computedKey = [project, namespace, label]
    .filter(Boolean)
    .join('_')
    .replace(/\s/g, '_');

  return md516(computedKey);
}

06 / Runtime Implementation

关键实现二：包装 vue-i18n 生成统一 $gt

把业务调用、资源检查、开发态收集和生产兜底都收束到一个函数中。

export function generateTransifyVueI18n(i18n, config) {
  if (!config.project) {
    throw new Error('project is required!');
  }

  return function (label, namespace, options) {
    const computedKey = generateKey({
      label,
      namespace,
      project: config.project,
    });

    if (!computedKey) return '';
    if (config.isShowKey) return computedKey;
    if (!i18n.te(computedKey)) {
      if (!config.isDev) return label;
      addTranslationKey(computedKey, label);
    }

    return i18n.t(computedKey, options);
  };
}

这里的核心取舍是：生产缺失时返回默认文案，避免出现不可读 Key；开发缺失时收集 Key，为后续上传和补齐翻译服务。

08
08 / Decisions

方案选择：在易用性、稳定性和安全性之间取平衡

这个项目的价值不只是写一个函数，而是把团队国际化流程中的几个关键取舍定下来。

决策点 可选方案 最终选择 理由
Key 来源 手写业务 Key / 文案生成 Key 文案生成 Key 降低接入心智，减少命名规范争议。
Key 形态 长字符串 / 完整 MD5 / 16 位 MD5 16 位 MD5 兼顾稳定性、长度和可识别性。
缺失翻译 显示 Key / 报错 / 返回默认文案 生产返回 label 保护用户体验，避免内部 Key 暴露。
上传 Token 浏览器一键上传 / CLI 上传 优先 CLI 减少浏览器保存敏感凭证的风险，便于 CI 集成。
